## 六、各任务详细方案

### 4a 基底魔改收尾与画布增强（依据 7.1、7.2）

**实施要点**：

1. **三并列入口**（需求四，缺口表「阶段4(画布入口)」行）：原始项目操作目录（`ModelViewerView`）提供
   「先复现 / 先使用 / 先拆解」三个并列指令，现状「先拆解」链路保留为其中之一。
   - 先复现：跳转/驱动模块二复现流程（后端 `POST /api/papers/{id}/reproduce` 已具备，缺前端入口衔接）。
   - 先使用：驱动模块三数据对比流程（阶段2 为脚本驱动 `run_dataset_pipeline.py`；本阶段以任务方式驱动或最小面板衔接，**不新做大界面**——界面范围待评审确认，先按任务化驱动实施）。
   - 先拆解：现状链路（结构分析 → 拆解 → 验证 → 入库）。
2. **形状校验提示中文化**：连线形状不匹配时给出中文文案 + 原因定位（哪一侧形状对不上）。
3. **画布新建结构化项目**：画布页提供「新建模型」入口 → `POST /api/projects`（`project_type=structured`）
   → 初始化空 `graph.json` → 进入画布；随后 4d-1 在这里挂 git 初始化。
4. **成组网络整体保存**：核实基底「成组保存为模块」路径在改造后的画布仍可用；有缺则补齐，
   保证成组网络可整体保存进画布模块库（localStorage，与 4b 的后端模块库合并展示）。
5. **守卫回归**：原始项目画布打开/修改必须被拒绝（D12）；后端模块库注入的只读性回归。

**验收判据**：三入口在原始项目页可点且各自进入正确流程；新建结构化项目画布可用；
形状不匹配提示为中文且指出原因；原始项目在画布只读。

### 4b 标准化模块接入收口（依据 7.2、7.3）

**实施要点**：

1. **params_schema 参数面板联动**：画布上后端模块节点的参数面板由 `module.json` 的
   `params_schema` 生成（可调项、类型、默认值），与标准节点参数面板同一交互形式。
2. **模块库注入守卫回归**：本轮已实现的「画布启动经 `GET /api/modules` 注入」补验收：
   - 后端有模块 → 节点库可见且可拖入画布、与标准节点混拼；
   - 后端不可用/无模块 → 静默降级仅本地模块（不报错、不覆盖 localStorage）；
   - 本地模块与后端模块同名不同源时展示可区分。
3. **版本引用边界**：画布引用模块的旧版本保持不变，可手动升级（数据设计七.3）。

**验收判据**：拖一个后端模块节点进画布，参数面板显示 `params_schema` 字段且可改；
后端停机状态下画布正常打开、本地模块仍在。

### 4c 新模型运行（依据 7.4、7.5；架构八.3）

**实施要点**：

1. **网络保存收口**：保存继续走 `PUT /api/projects/{id}/graph`（不新建 `POST /api/networks`，
   避免双写；network_id 即结构化项目 project_id——设计文档 7.4 的「POST /api/networks」按此登记偏差，
   如需改设计文档走变更记录）。保存成功即触发 4d-1 的 git 提交。
2. **导出 API**：`GET /api/networks/{id}/export`——前端用 `codeCompile` 生成代码（已有下载能力），
   后端端点返回「GraphIR 落在服务端时的再生成代码」作为兜底，保证导出两端一致。
3. **训练运行 API**：`POST /api/networks/{id}/run`，请求体含：
   - 数据集选择（复用阶段2 预处理产物：`data/projects/*/datasets/*`）；
   - 目标环境（默认复用父原始项目的独立环境，可选新建；环境不可用 → 引导先走模块一建环境）；
   - 训练配置（epoch 数、批大小、学习率）。
   后端流程：导出代码 + 训练脚本模板（`train.py`：数据加载 ← 预处理产物、模型 ← 导出代码、
   训练循环、指标回写）→ 写入结构化项目工作区 → 经 `proc_util` 在项目独立环境执行 →
   任务队列轮询（复用 `task_manager`）→ 指标与运行记录落库（`run_record`，`run_type=train`）。
4. **运行面板 UI**：画布页新增运行面板（数据集下拉、环境选择、训练参数、启动按钮、进度与指标展示）。
5. **验收样例（M4 主链路）**：后端模块（取 `mod_611e10504a9b0e61` 或 m3 样例模块）+ 标准节点
   混拼一个小模型（如 Linear→ReLU→Linear 级），导出代码在独立环境 CPU 训练数步走通即可
   （smoke 级，不追求收敛）。

**验收判据**：运行面板发起训练 → 后台任务完成 → 指标显示 → `run_record` 新增 `run_type=train`
成功记录；M4 主链路整体走通。

### 4d-1 版本管理底座：git 初始化与保存即提交（依据 7.6、D8）

**实施要点**：

1. **git 初始化**：结构化项目创建时（含画布新建与拆解入库生成）在项目工作区 `git init`（后端子进程）。
   提交身份用仓库级/项目级配置，不依赖全局 git 配置；命令失败错误透出、不静默。
2. **保存即提交**：`PUT /api/projects/{id}/graph` 成功后自动 `git add graph.json + git commit`；
   版本元数据 `network_version.json`（输入输出规格、运行结果摘要、保存时间）随提交入库。
3. **运行即提交**：训练运行完成（4c）也生成一次提交，元数据含指标摘要。
4. Windows 环境：git 操作由后端统一封装（`git -c` 参数、编码处理），不依赖 shell 特性（《开发计划》九风险）。

**验收判据**：新建结构化项目后工作区存在 `.git`；两次保存产生两次提交；`network_version.json`
随每次提交变化。

### 4d-2 版本管理可视化：版本树、对比、回退（依据 7.6）

**实施要点**：

1. **版本树 API**：`GET /api/versions/{network_id}/tree`——读 git 提交历史，返回版本节点
   （提交号、时间、元数据摘要、父子关系）。
2. **对比 API**：`GET /api/versions/{network_id}/compare?v1=&v2=`——代码差异（git diff）+
   参数差异表（两版 `graph.json` 的节点参数逐项比对）。
3. **回退 API**：`POST /api/versions/{network_id}/rollback`（body 带目标版本）——检出目标历史版本
   为当前工作状态，回退动作本身记为一个新提交（需求五.3）。
4. **版本树 UI**：画布页版本面板——树/列表展示演化关系、选中两版本看代码与参数差异、回退按钮。
5. 回退后画布重新加载目标版本图，继续编辑；编辑后保存生成新版本（树上出现分叉）。

**验收判据**（M5 三条）：版本树展示演化关系；任意两版本对比出代码与参数差异；
回退后画布内容变为目标版本、继续编辑保存后产生新版本节点。

```
M4：画布新建结构化项目（git 初始化）
  → 拖入后端模块节点 + 标准节点混拼

  → 版本树渲染 → 对比任意两版本（代码 + 参数差异）
  → 回退到历史版本 → 画布内容变化 → 继续编辑保存 → 回退记为新版本（树分叉）
```

## 八、M4/M5 验收落地方式

1. **脚本化验收**：新增 `scripts/m4_acceptance.py`（沿用 `m3_acceptance.py` 模式）——
   M4/M5 各条目逐项断言（git 提交数、版本树结构、对比差异、回退后状态、`run_record` 记录）。
   训练冒烟用 CPU 小模型，控制时长。
2. **浏览器实测**：按 AGENTS.md 规矩——前端改动后**必须真正打开一次构建产物**
   （无头浏览器加载，看画布与版本面板渲染、控制台零报错），不能只看构建退出码。
3. **回归**：每任务完成后跑 `backend\.venv\Scripts\python.exe scripts/run_tests.py` 全绿 +
   `npm run lint` 0 问题 + `npm run build`；后端改动重启进程后再验。
   前端改动后按 AGENTS.md 规矩**真正打开构建产物**验一次——本阶段起用
   `backend\.venv\Scripts\python.exe scripts/ui_check_4a.py`（4a 已实测 22/22，见十一）。
4. **不需要模型凭证也能验收**：4a～4d 主链路均不依赖大模型（运行、版本、画布均为本地能力），
   验收不因凭证缺失而阻塞；三并列入口中「先复现」的跳转衔接可用无凭证时的明确失败行为验证闸门。

## 九、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 基底魔改回归 | 改造后画布既有能力（拖拽/连线/导出）坏掉 | 以基线提交 `d861551` 做 diff 回归；复跑 GB-1 导出 harness；每次改动后构建产物无头浏览器实测 |

| 混拼模块缺形状信息 | 连线形状校验无从比较 | 依赖 `module.json` 的 input_spec/output_spec；缺失时按现占位通道降级为提示而非阻断 |
