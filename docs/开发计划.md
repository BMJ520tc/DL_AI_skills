## 一、文档说明

### 1. 定位

本文档基于《系统架构设计》的模块依赖关系与《模块详细设计》的章节,将开发工作划分为阶段与里程碑,给出任务分解、依赖关系与验收标准。计划按阶段与里程碑排列,不绑定具体日期;实施时按团队人数与投入量化为排期。

### 2. 引用约定

任务分解表中的"设计依据"引用《模块详细设计》小节号(如 2.3),术语与决策编号沿用《系统架构设计》。

## 二、阶段划分依据

1. **关键路径为一 → 三 → 四 → 五 → 六**:模块三(基准与跨数据集)依赖模块一的环境能力;模块四(拆解)依赖模块一的环境与结构分析;模块五依赖模块四的标准化模块、模块三的预处理、模块一的环境;模块六依赖全部模块的数据产出。
2. **模块二(复现)不在模块五的关键路径上**:多人团队可与模块三并行开发;单人团队置于模块三之后、模块五之前;但必须早于阶段 5(模块六需要论文数据入库)。
3. **阶段 0 必须在开工前完成四份设计文档评审**:避免边写边改返工;此后每个里程碑结束更新对应设计章节并升版本(见十二)。
4. **模块五内部顺序 4a → 4b → 4c → 4d**:先魔改基底打通标准节点闭环(4a),再接标准化模块(4b,依赖 M3),运行能力(4c)依赖 M1 与 M2a,版本管理(4d)最独立故最后。

## 十二、文档同步规则

1. 设计文档是活文档:每个里程碑结束,修订对应设计章节并升版本文档版本(见各阶段"文档同步"行)。
2. 需求文档(功能需求.md)不修改;需求变更时,经评审后修订设计文档并在变更记录登记。
3. 待决策项(D-x)已在《系统架构设计》附录 A 定案,实施中如需变更,须在附录 A 记录变更原因与日期;开放项(O-x)在实施期关闭时,从附录 B 移除并记录结论。
4. 代码实现与文档不一致时,以修订文档或修订代码二选一解决,不允许长期漂移。
