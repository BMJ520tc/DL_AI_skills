## 一、文档说明

本文是阶段6（联调与验收）的实施草案，按《开发计划》十一节的任务 6.1～6.6 展开：任务分解、
实施顺序、验收方式与风险。结构沿用《阶段3实施方案》《阶段4实施方案》《阶段5实施方案》。

**本阶段的特点**（决定工作量分布）：阶段0～5 的能力已全部验收，阶段6 不新增「业务功能」
（6.6 除外），核心是**串联与核对**——推荐路径 / 多数据集与综合分析 / 自迭代三条主链路端到端
走通（6.1～6.3）、缺陷与缺口清零（6.4）、文档定稿（6.5）；6.6「一键封装」是评审定案的新增
需求，拆为**先行的一键启动链路（6.6-a）**与**后置的打包（6.6-b）**两半：6.6-a 先行让三条
联调链路直接跑在「一键启动」形态上，6.6-b 后置避免联调缺陷反复触发打大包。

## 六、各任务详细方案

### 6.6-a 一键启动链路（先行；依据探索稿 v1.0 定案路径第 1 条）

**实施要点**：

1. **`start.bat`**：自检（`frontend/dist` 在否、Python 在否、端口占用检测）→ 起后端（uvicorn，
   端口被占即中止，沿用 `ui_check_*` 的防串台口径）→ 自动开浏览器。开发/联调期即用。
2. **后端静态挂载**：`app/main.py` 挂 `StaticFiles` 服务 `frontend/dist`，**含 SPA fallback**
   （前端路由回退 `index.html`）；挂载可开关（如 `DL_AI_SERVE_STATIC`，打包模式默认开、
   开发模式默认关——不破坏既有 `vite preview` / dev server 工作流）。
3. **数据目录可覆盖**：`config.py` 的 `DATA_DIR` 支持环境变量 `DL_AI_DATA_DIR` 优先；
   打包模式缺省 `%LOCALAPPDATA%\DL-AI-skills\data`；开发模式保持项目根 `data/` 不变
   （不动真实数据、不破坏既有脚本）。**首启迁移提示**：打包环境下若检测到既有数据目录
   （如项目根 `data/`）且新数据目录为空 → 弹提示「沿用旧目录（配置指向旧目录，不复制）/
   初始化新目录」，一次性选择并记标记。
   **（实施时序登记 2026-10-05：本条随 6.6-b 冻结形态一并实现——其触发场景仅在打包态存在，
   6.6-a 开发态无可验证环境；6.6-b 的干净环境验收一并覆盖。）**
4. **凭证设置页（评审裁定第 6 项）**：后端 `GET/PUT /api/settings/credentials`——凭证写入
   数据目录下本地配置文件（不进版本库、不打日志；GET 只返回「已配置/未配置 + 掩码」，
   不回显明文）；前端顶栏「设置」入口 + **首启未配置凭证时弹「设置凭证」页**（可跳过，
   跳过则大模型步骤按规矩 7 如实失败）。不做「测试连接」假通过——保存后由后续任务自然验证。
5. **首启自检引导（评审裁定第 2 项）**：后端 `GET /api/system/env-check` 返回
   `{git: 找到否+版本, python: 找到否+路径, conda: 找到否+路径, data_dir: 路径+可写性,
   static_served: 是否挂载}`；前端引导页/横幅展示结果——git/Python 缺失给安装指引链接 +
   「重新检测」按钮；conda 仅提示、不阻断（保留 conda 分支，评审裁定第 5 项）。

**验收判据**：start.bat 一键起后端并开浏览器、界面经**后端静态挂载**打开且控制台零报错；
数据目录按覆盖规则生效；凭证页首启弹出、保存后 GET 只见掩码；env-check 在「缺 git」模拟下
正确报缺并给出指引。

### 6.1 推荐路径联调（依据 9.1、需求四推荐顺序）

**走通口径（真实数据 + 真建环境，沿用阶段4/5 严口径）**：真实论文（复用已入库真实论文）→
代码仓库加载（完整克隆/抽址自动克隆）→ 建真实独立环境 → 结构分析报告 → 复现实验 → 可信度
结论 → 模块四拆解入库（真实模块）→ 画布拼装（真实结构化项目）→ 真实 CPU 训练 → 版本留存。
其中「复现实验 / 可信度结论 / 拆解入库」为 agent 步骤（需要凭证，规矩 7）。

**逐环断言**：每环产物落库（paper/reproduction_result/credibility_conclusion/module/
结构化项目/run_record/git 版本）、无 5xx、界面可达。

**验收判据**：全链路一次走通并留痕，证据链可复核（库记录 + 项目 git log + run_record）。

### 6.2 多数据集与综合分析联调（依据 9.2）

**验收判据**：对比图表产出正确；多模型报告结构完整（同口径统一/一致分歧/归因/融合前后指标）。

### 6.3 自迭代闭环联调（依据 9.3）
