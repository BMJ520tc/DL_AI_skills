### 补充 A：前端 AI 助手（对应 ③）

> **（拟）需求六.3 / 新章节：前端 AI 交互**
> 在前端提供与 AI 助手对话的界面。用户可就**当前上下文**（当前项目 / 论文 / 模型 / 知识库 / 运行记录）提问，助手解释现状、给出建议；助手可经**既有能力**（检索知识库、查运行记录、读结构报告）作答。
> **闸门**：涉及**不可逆动作**（发起训练 / 入库 / 删除）必须经用户显式确认；无模型凭证时对话如实失败，不伪造结论（规矩 7）。
> **边界**：一期只做「只读助手」（能查能答、能给建议）；「助手代为执行动作」列为后续可选项。

### 补充 B：架构级自迭代（对应 ②）

> **（拟）需求六.1 延伸：架构级改进闭环**
> 自迭代闭环除超参外，支持**架构级改进**：把蒸馏知识（如「某结构在此类数据上更优」）与入库的**标准化模块**，作为**架构改动建议**带入新任务；**用户确认后**改动落到画布结构（换模块 / 加层 / 改连接），并可重训、对比、把新结论蒸馏入库，形成「建议 → 改架构 → 重训 → 蒸馏」的闭环。
> **边界**：改动**必须经用户确认**（不自动改画布）；沿用版本管理（每次改动 = 一个新版本）；仍不落权重（与既有「保留最优」口径一致）。
> **连带**：需相应修订《模块详细设计》7.5 的「只搜超参不搜结构」边界表述。

### ③续：平台动作工具 + UI 确认弹窗（**已完成，2026-10-05**）

**背景**：用户要求「适当给助手几件能动手的」，且确认粒度选 **UI 弹窗**（硬闸门）。

- **给（可自建、可回退）**：`platform_create_project`（原始项目）、`platform_create_env`（建独立环境）、`platform_run_analyze`（结构分析）。**仅在「可写」模式暴露**（只读模式工具列表里没有，直接调用也拒）。
- **不给（不可逆/昂贵/破坏性）**：删除项目、发起训练、入库、回滚版本、改画布 —— 仍只指引去界面。
- **确认**：**UI 弹窗**——助手要执行动作时，后端经 SSE 推一条「确认请求」→ 前端弹出确认卡片（含动作与参数）→ 用户点确认/取消 → 后端把决定回给工具，工具才执行；未确认（取消/超时）即不执行，工具返回 `executed=false`。
- **实现**（沿用评审登记的方案）：
  - 动作工具跑在 **stdio MCP 子进程**里（`app/mcp/knowledge_mcp.py`），跨进程拿不到后端内存 → 确认握手经 **HTTP 回环**（MCP `POST /api/assistant/confirm` → 后端登记并经 SSE 推给该会话前端 → 用户裁定 → MCP `GET /api/assistant/confirm/{id}` 轮询取决定）。
  - 会话上下文（`ASSISTANT_SESSION_KEY` / `ASSISTANT_MODE` / `DL_AI_BACKEND_URL`）由后端挂载 MCP 时注入（`agent_service._knowledge_mcp`）；确认登记表 `_CONFIRMS` 与会话队列 `_SESSION_QUEUE` 在 `assistant_service`（进程内）。
  - 获准后 MCP 调**后端既有 API** 执行（`POST /api/projects`、`POST /api/projects/{id}/env`、`POST /api/projects/{id}/analyze`）——MCP 进程不入队。
