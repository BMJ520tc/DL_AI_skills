## 一、说明

### 1. 定位

本记录把各阶段「里程碑门槛」的实际验收结论、证据路径与**已知边界**集中归档。
此前只有阶段 1 留有正式验收记录（《阶段1实施方案》十一），阶段 0/2/2' 的结论散落在
《模块详细设计》版本说明与 commit message 中，无法从《开发计划》直接读出进度。
本记录与《开发计划》的勾选（见 A2）互为对照。

### 2. 判定口径

- 以《开发计划》各阶段「验收标准」为验收项，逐条给出**通过 / 部分通过 / 不适用**。
- 每项必须附可复核证据：命令、文件路径或数据库记录；不接受口头结论。
- 「已知边界」= 里程碑门槛通过、但计划中任务产出物未完全交付或验收样例不代表真实场景的部分，
  逐条对应《阶段收口任务清单》的任务 ID，收口后回填。

## 七、收口期验证与新增发现（2026-10-01 收口执行）

按《阶段收口任务清单》执行收口，**用真实数据与真实浏览器/接口验证**时又暴露 6 处实现缺陷，
均已修复并带回归用例（详见收口清单 B3~B7 与 CORS 补漏）：

| 编号 | 缺陷 | 触发场景 | 影响 | 修复/验证 |
|---|---|---|---|---|
| B3 | compare 在 agent 无产出时仍落库空「使用建议」 | 模型端点不可用 | 「起草失败」被伪装成「已产出待确认」，问题延后到用户确认才暴露 | `_require_guidance()` 失败闸门 + 3 用例 |
| B4 | 知识库 MCP 工具未进白名单 | `permission_mode="dontAsk"` | agent **查不了知识库**（工具调用被直接拒绝），与 2.5「查询知识库」能力设计不符 | `allowed_tools()` 注入 `mcp__knowledge__knowledge_search` + 9 用例 |
| B5 | 图片压缩包预处理把 `train/test` 当标签，且解压到临时目录 | 真实 Zenodo 图片数据集 | 1400 行标签全错；CSV 中图片路径在运行后被删除而失效 | 跳过 split 目录 + 解压落产出目录 + 5 用例；实跑 labels=cat/dog、split=train/test、路径存在 |
| B6 | 对齐规则兜底把 DB 的 JSON 文本当列表遍历 | agent 不可用 → 规则兜底 | 对齐必然报「缺少字段信息」而失败 | `_as_json()` 解析 + 4 用例 |
| B7 | 「自带数据」按路径前缀取首条 | 外部数据集预处理进项目目录 | 外部数据集被当成基准来源，来源与目标退化为同一条 | `find_self_dataset()` 按来源过滤 + 2 用例；实跑 source_dataset_id 正确 |
| — | 后端无 `CORSMiddleware` | 前端 dev server 直连后端 | 浏览器跨域被拦，前端只能靠代理规避 | 补本机来源 CORS + 3 用例 |

**真实数据收口结果（E1）**：Zenodo `records/5226945`（Cats and Dogs sample，CC-BY-4.0，32.6MB）
下载 → 注册真实 URL → 预处理 1400 行（cat 655 / dog 745，train 1000 / test 400）→ 规则兜底对齐
（`label_merge {cat→Cat}`）→ 确认闸门 → 跨数据集评估 → 三张图正常生成。对比表：

| 指标 | baseline（自带） | cats-dogs-sample（真实公网） | public-pub（本地样例） |
|---|---|---|---|
| accuracy | 0.7917 | 0.4993 | 0.2000 |
| f1 | 0.7913 | 0.4988 | 0.2000 |
| loss | 0.275 | 0.275 | 0.295 |

**阻塞（C2/E2）**：当前环境没有任何模型凭证（无 `ANTHROPIC_*` 环境变量、`.claude.json` 无
`oauthAccount`/`primaryApiKey`、无 `.credentials.json`），agent 任务返回 `Not logged in · Please run /login`；
早期会话启动的旧进程（端口 8010）仍持有凭证但代码为旧版。因此 agent 侧 MCP 闭环复验与
M2b 真实论文复现需在提供凭证（API key 或 `claude /login`）后继续。
