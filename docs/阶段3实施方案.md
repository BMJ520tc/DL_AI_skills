## 六、各任务详细方案

### 3.1 模型解析与 IR（依据 6.1、O4）

- **输入**：`reports/structure_report.json` 的 `module_hierarchy` + `train_flow`/`inference_flow` 定位模型定义文件与入口类。报告不存在 → 409 提示先跑模块一 `POST /analyze`。
- **处理**：agent 任务（`agent_service.run_sync(prompt, cwd=source, output_schema=IR_SCHEMA, max_turns=60, timeout_s=1800)`，prompt 内联 f-string，现惯例）解析模型定义 → 输出 IR → `validate_ir` 硬校验 → 写 `reports/ir.json`。**结构化输出缺失时重试**：最多 `DECOMPOSE_AGENT_RETRIES`（默认 3）次、总预算 `DECOMPOSE_AGENT_BUDGET_S`（默认 3600s），单次 timeout 取 `min(1800, 剩余预算)`；预算用尽即任务 failed 并记原因。任务级超时对应 `TASK_TIMEOUTS["decompose"]=3900`（必须大于 agent 预算，否则任务先被取消）。
- **IR schema**（`reports/ir.json`）：

```json
{
  "schema_version": "1.0", "project_id": "…", "source_file": "models/resnet.py",
  "entry_class": "ResNet", "task_type": "classification",
  "input_spec": {"shape": [1,3,224,224], "dtype": "float32"}, "root_id": "n0",
  "nodes": [{"id":"n0","kind":"module|leaf|container|op","class_name":"ResNet|nn.Conv2d|nn.Sequential|add",
             "module_file":"models/resnet.py","module_path":"layer1.0.conv1",
             "params":{},"parent_id":null,"input_shape":null,"output_shape":null,
             "code_hint":null,"uncertain":false}],
  "edges": [{"from":"n0","to":"n1","tensor_shape":null}]
}
```

  字段语义：层级树由 `parent_id` 隐式表达 + `root_id` 标入口（不双写显式树）；`kind` 四类——`module`（自定义 nn.Module 子类）、`leaf`（nn.* 层）、`container`（Sequential/ModuleList，子节点经 parent_id 归属）、`op`（函数式操作 `+`/cat/F.relu，`code_hint` 存内联表达式）；`module_path` 是 named_modules 路径，为 trace 对齐运行时实例的锚点；形状 agent 能确定则填，否则 null（前端显示「未知」，由 3.2 前置的 trace 回填）。
- **prompt 要点**（O4）：只读不改文件；每 nn.Module 子类一节点；Sequential/ModuleList 展开为 container+子节点；`+`/cat/F.relu 转 op 节点；module_path 必给；拿不准标 `uncertain:true`；task_type 从结构判定（classification/regression/segmentation/detection/generation/embedding/other）。
- **validate_ir（宿主侧确定性函数）**：nodes 非空、id 唯一且非 Python 关键字、params 键为合法关键字参数名、parent_id/edges 引用存在、kind 合法、root_id 存在、**leaf 必须在白名单内且必填构造参数齐备**（`LEAF_REQUIRED_ARGS`：Conv2d 需 in/out_channels+kernel_size、Linear 需 in/out_features、BatchNorm2d 需 num_features、ReLU/Pool/Dropout 无需参数…；白名单外或参数不全且无 code_hint → 拒绝生成，避免生成代码运行期 AttributeError/TypeError）、**二元 op（add/sub/mul/div/matmul/bmm）至少两条入边**、op 必须有 code_hint 或白名单类名。校验不过 → 任务 failed、error 写缺失项清单、**不写 ir.json**（agent 原始输出留 `data/agent_tasks/{task_id}/result.json` 可回溯），并落 run_record(status=failed) 供检索。
- **接口**：`POST /api/projects/{id}/decompose`（触发）、`GET /api/projects/{id}/ir`（附 `verification_status: none/valid/stale`）、`PUT /api/projects/{id}/ir/nodes/{node_id}`（调参回写，仅 params）。
- **落位**：`backend/app/services/decompose_service.py`（新）+ `backend/app/api/decompose.py`（新，仿 analysis.py `_require_original` 闸门）+ `main.py`（router + lifespan 注册）+ `task_manager.TASK_TIMEOUTS` 增 `decompose: 3900`。run_record：`run_type="decompose"`。**触发端点前置**：`decompose_precheck` 同步校验 `structure_report.json` 存在，缺失即 HTTP 409（任务内仍保留同校验兜底）。

### 3.2 trace 补形状（依据 6.1「形状缺失经 trace 补充」）

- **脚本**：`scripts/trace_shapes.py`，签名 `python trace_shapes.py <source_dir> <ir_json> <out.json>`（脚本与宿主同序：source 在前），在**项目环境**执行（`analysis_service._project_python`；环境未就绪 → 任务 failed 提示先完成环境创建）。脚本落盘产物为 `{"shapes": {path: {input_shape, output_shape}}, "order": [{path, class_name}…]}`，**由宿主 `_merge_shapes` 合并进 ir.json**（脚本不直接改写 IR，避免并发覆盖；合并只填 null 项，幂等）。
- **流程**：宿主读 IR 判断形状缺失 → 加载 `source_file` 的 `entry_class` → `torch.randn(*input_spec.shape)` 构造输入 + `register_forward_hook` 挂子模块 → 按节点 `module_path` 定位实例回填形状；**无 module_path 的节点按「class_name + 出现次序」与 traced 的 `order` 配对兜底**（并借此补出 module_path）。
- **接口**：`POST /api/projects/{id}/decompose/trace`（触发任务）。decompose 完成后任务 progress 记 `shapes_missing: true|false` 引导前端提示。
- **落位**：`scripts/trace_shapes.py` + decompose_service 任务 `decompose_trace`（TASK_TIMEOUTS 增 900）。run_record 同类型落库。

### 3.3 代码再生成（依据 6.3、新定案 2）

- **引擎**：`backend/app/services/ir_codegen.py`（新，纯函数无 IO/无 subprocess，输出 str）。生成策略：先 `validate_ir` 后拓扑排序；叶子白名单（nn.Conv2d/Linear/BatchNorm2d/MaxPool2d/ReLU/…，常量维护）直接实例化 `self.x = nn.X(**params)`；自定义 module 每节点输出独立类（`Decomp_{id}` 命名，`__init__` 实例化子节点、`forward` 按子树 edges 调用，**自包含不 import 源项目**）；container → `nn.Sequential(...)`；op → code_hint 内联（多入边按声明序编号变量）；变量命名 `var_{node_id}`，forward 拓扑序生成，末尾返回根节点输出。IR 不完整 → 抛 `IrIncompleteError`。
- **接口**：`POST /api/projects/{id}/decompose/regenerate` **同步返回** `{code}`（确定性毫秒级，不建任务、不落盘）。verify 任务内部自行调用引擎生成到运行目录（保证验证对象恒等于当前 IR）。
- **落位**：`backend/app/services/ir_codegen.py` + decompose.py 端点。

### 3.4 两步验证（依据 6.4、新定案 1/3/4）

- **脚本**：`scripts/verify_decompose.py`，签名 `python verify_decompose.py <source_dir> <ir_json> <regenerated_py> <out.json> <seeds> <rtol> <atol>`，**必须在项目环境执行**（需 torch 加载两模型）。宿主侧编排仿 `baseline_service.run_eval`：生成代码到 `ws/runs/decompose/verify/{task_id}/regenerated.py` → `asyncio.to_thread(subprocess.run, [python, ...], cwd=run_dir)`（Windows：命令恒 list、无 shell）。
- **权重同源（前置步骤，必须先做）**：两模型各自随机初始化，直接比对必然不等（文档示例的 `max_rel_err: 0.0` 在此步缺失时不可达）。脚本按结构比对所依据的**位置对应关系**，把原模型 `state_dict` 的张量逐一拷入再生成模型（形状一致者，含 BN running 统计），再跑多种子输入；故数值比对检验的是**连接关系与拓扑顺序**是否忠实，而非初始化巧合。`verification.numeric.weight_source = "original"` 记录该事实。
- **判定算法**（全部 CPU + eval() + `torch.manual_seed` 固定）：
  1. **结构比对**（按位置，非按名字——两模型的子模块命名不同）：**带参数层**（叶子白名单层 + 自定义 module）的类型名序列逐位比对、总参数量相等、`state_dict` 逐位置形状比对、每组种子输入 forward 后输出 shape 相等；差异记 `diff_layers`。**层数按带参数层计**，模块总数（含 ReLU/Dropout/空 Sequential 等无参层）只作参考信息、不参与判定——静态等价描述下无参层允许被拆分或复制（如复用同一 ReLU 实例的模型被展开为多个 ReLU），否则样例 ResNet 这类模型永远无法通过。
  2. **数值比对**：多种子输入下逐元素相对误差 `max(|test−ref|/(|ref|+1e-8))`（ref=原模型）与绝对误差 `max(|test−ref|)` 双判据（满足其一即通过），阈值见新定案 3；**失败定位差异层**：两模型内部输出按 named_modules **位置对齐**（路径名不同，按名字求交集只剩根节点），取不一致层按深度降序，路径回报原模型命名；定位结果同时写入 `numeric.per_seed[].diff_layers`。
- **退出码约定**：比对不过（业务失败）**0 退出**（结果在 JSON——验证失败是正常业务结果）；脚本异常（模型加载失败等）非 0。
- **verification.json**（= 数据设计七.1 verification 字段内容，落 `reports/verification.json` 覆盖式）：

```json
{
  "schema_version": "1.0", "verified_at": "…", "project_id": "…",
  "ir_hash": "sha256(规范化 ir.json)…",
  "seeds": [42,1337,2024], "tolerance": {"rtol": 1e-5, "atol": 1e-6},
  "structure": {"passed": true, "layer_count": {"original": 68, "regenerated": 68},
    "param_count": {"original": 11173962, "regenerated": 11173962},
    "module_count": {"original": 84, "regenerated": 85, "note": "含无参层，参考信息，不参与判定"},
    "layer_sequence_match": true, "param_shapes_match": true, "output_shape_match": true, "diff_layers": []},
  "numeric": {"passed": true, "weight_source": "original",
    "per_seed": [{"seed":42,"max_rel_err":0.0,"max_abs_err":0.0,"passed":true,"diff_layers":[]}]},
  "overall": "passed|failed", "failure_reason": null
}
```

- **接口**：`POST /api/projects/{id}/decompose/verify`（触发）、`GET /api/projects/{id}/decompose/verify`（最近结果）。
- **失败语义**：验证不过 → run_record（`run_type="decompose_verify"`）status=failed + error=failure_reason + artifact_path=verification.json（可检索供后续 agent 改进，6.4/架构九.4），**任务本身 success**；脚本异常 → 任务 failed。任务类型 `decompose_verify`（TASK_TIMEOUTS 增 2400；脚本自身上限 1800s）。
- **落位**：`scripts/verify_decompose.py` + decompose_service 任务。数值比对输出是张量比对，不涉及 `contracts.normalize_metrics`/CANONICAL_METRICS（模块五契约）。

### 3.5 标准化模块入库与结构化项目生成（依据 6.5、D10、D12）

- **入库前置校验**（**请求期同步**，`ingest_precheck` → API 映射 HTTP）：ir.json 存在（缺 → 404）→ verification.json `overall=passed`（未过 → 400）→ `verification.ir_hash == 当前 ir_hash`（stale → 409「请重新验证」）→ 同 module_id+version 已存在 → 409。后台任务内保留同套校验兜底（防请求后状态变化）。
- **module_id / 版本**：见新定案 5。
- **模块包落位**（数据设计七.1 目录）：`data/modules/{module_id}/{module_version}/` = `module.py`（A3 引擎再生成）+ `module.json` + `assets/`（空目录预留权重）。
- **module.json 字段与来源**：

| 字段 | 来源 |
|---|---|
| module_id / module_version | 签名/递增规则 |
| name | `entry_class` |
| description | `f"从项目 {project_id} 拆解的 {entry_class}（{task_type}）"` |
| source_project_id | 原始项目 id |
| source_paper_id | null（新定案 6） |
| task_type | IR.task_type（入库 body 可覆盖，前端下拉修正） |
| input_spec / output_spec | IR 根节点 input_spec / 根节点 output_shape 包 `{"shape":…}` |
| params_schema | 根节点 params 派生 `{参数名: {type, default}}` |
| tags | `[task_type, project.source, "decompose"]` |
| verification | verification.json 全文嵌入 |
| saved_module_compat | `{id, name, version, handles:{inputs:["in"],outputs:["out"]}, description, graph_ref: 结构化项目id, graph, createdAt, updatedAt}`（D10 兼容基底 SavedModule；`graph_ref` 指向结构化项目的 graph.json 作为权威副本，**同时内嵌 graph 快照**——基底 `SavedModule.graph` 为必填字段，只存引用会让模块在画布侧不可用，故此处不采用「只存引用」的字面口径，改为一并内嵌） |
| path | 模块包内 module.json 的绝对路径（`data/modules/{module_id}/{version}/module.json`） |

- **DB 写入**：module 表 INSERT（schema 已就绪）；`unified_index`：data_type=module、ref_id=`{module_id}:{module_version}`、title=name、summary=`f"{task_type} 模块 | 参数量 {param_count} | 验证通过 | 来源项目 {source_project_id}"`、tags、keywords（**不写 model_name**，避免把「模型过滤」维度污染成模块名）。`knowledge_service` 增 `record_module`/`list_modules`/`get_module`/`delete_module`（注意 module 表复合主键 `(module_id, module_version)`，`_TABLE_PK` 单主键假设需特判：`get_item("module", ref)` 与 `get_module_by_ref` 按 `{module_id}:{version}`（或裸 module_id 取最新）拆分 ref）。事务：先写模块包临时目录 → DB 事务（module 表 + unified_index）成功 → rename 正式目录；**并发下版本被抢占 → 递增重试（≤3 次）**；任一步失败 → 删临时目录、`delete_module` 回滚 DB 行、`delete_project` 清掉半成品结构化项目。
- **结构化项目生成**（D12、数据设计八.1）：`project_manager.create_project("structured", source="decompose", name=f"{原名}（拆解）", parent_project_id=原项目id)` → 写 `ws/graph.json`（**GraphIR v2**，由后端新增 `ir_to_graphir(ir)` 确定性转换：node type 统一 `"ir_node"`、data 存 `{kind, class_name, params, __shape}`、handles 由 edges 派生、parentId 镜像层级、position 留空由前端 layout）→ 项目 status 置 `ready`（structured 不适用 loading/env_ready/analyzed 流转）→ module.json `saved_module_compat.graph_ref` 回写该 id。
- **接口**：`POST /api/modules`（body `{project_id}`，触发入库任务）、`GET /api/modules`（module 表全量列表，供阶段5 拉取）；`GET/PUT /api/projects/{id}/graph`（结构化项目 graph.json 读写，require_type structured 闸门）。
- **落位**：`backend/app/api/modules.py`（新）+ decompose_service 任务 `module_ingest`（TASK_TIMEOUTS 增 300）+ knowledge_service 增量 + projects.py graph 端点。

## 九、风险与应对

- **agent 解析质量是最大不确定性（O4）** → prompt 要点（module_path 锚点/uncertain 标注/不臆造）+ validate_ir 硬校验 + trace 形状兜底 + **数值比对硬闸门**（任何解析错误都会在结构/数值比对暴露并定位到层）；先样例后 GEARS 渐进打磨。
- **数值比对环境** → 验证脚本强制 CPU + eval() + 同种子；环境未就绪明确报错「先跑通模块一」（先例 baseline_service）；Windows 子进程命令一律 list 形式、无 shell。
- **前端改造量（无路由无 API client 是现状最大缺口）** → 最小方案（顶层 state 切换不引 react-router、FlowEditor 仅 props 注入、查看器复用 DiagramView/CodeViewer/ELK）；FlowEditor initialGraph 注入是风险点，用 `key` 重挂载隔离。
- **module 复合主键** → 专用存取函数 + get_item 特判，不泛化改动通用代码。
- **解析大模型的轮数/超时** → decompose max_turns=60/timeout=1800（样例 ~70 节点、GEARS ~百级）；结构化输出失败重试 3 次已内建。
