## 一、需求来源与目标

**来源**：用户 2026-10-04 提出——把本项目封装成一个**完整的、可一键执行的程序**；
要求**在阶段6 之前先探索方案**（即本稿），评审定案后再落实施任务。

**目标表述（探索口径）**：拿到分发产物的人，双击一个入口（或一个安装包装完后的快捷方式），
程序自行完成：启动后端 → 提供界面（浏览器打开）→ 数据目录就位；不要求使用者会装 Python、
装 git、敲命令。

**边界（本稿不动的东西）**：
- 需求原文 [《功能需求.md》](../功能需求.md) 不改；本新需求经评审后按《开发计划》十二.2
  在《开发计划》登记任务、《系统架构设计》登记设计。
- 「一键执行」指**平台程序本体**的一键化。项目级能力不在其中：给项目建独立环境时仍要
  联网装依赖（torch 等，按项目要求），调用大模型仍需使用者提供凭证——这两点属系统固有
  能力边界，封装只负责把它们做得可引导、可配置。
- 与《开发计划》13.1 的关系：13.1「对外分发打包与依赖说明」原列二期，本需求把**方案探索**
  提前到阶段6 前；**实施已定案放阶段6**（2026-10-05 评审，任务 6.6）。

## 二、现状盘点（要封装的到底是什么）

| 组成 | 现状 | 体积参考 |
|---|---|---|
| 界面 | React + Vite 构建产物 `frontend/dist`；当前由 `vite preview`（开发/自检场景）提供，后端 FastAPI **未**挂静态目录 | 2.6 MB |
| 后端 | FastAPI + uvicorn，Python 3.14 项目内虚拟环境 `backend/.venv`；依赖见 `backend/requirements.txt`（fastapi/uvicorn/pydantic/claude-agent-sdk/docker/pandas/numpy/Pillow/openpyxl/pymupdf4llm/pdfplumber），**不含 torch**（训练在项目独立环境里跑） | site-packages 约 440 MB（含 pip 缓存；打包后量级 300~500 MB） |
| 数据 | SQLite 库 + 文件目录，默认 `PROJECT_ROOT/data/`（`backend/app/config.py` 硬编码） | 随使用增长 |
| 运行期外部依赖 | ① **git 命令行**（版本管理直接调 `git`）；② 建项目独立环境需要**可用 Python 解释器 + pip**（venv 分支，`ENV_VENV_PYTHON` 可指定）与**本机 conda**（conda 分支，探测 `CONDA_PATH`）；③ pip 联网装依赖（已支持国内镜像 `PIP_INDEX_URL`）；④ 大模型凭证（agent 步骤，`claude_agent_sdk` 内置 CLI，`DISABLE_AUTOUPDATER=1` 钉版本）；⑤ docker 仅探测 CLI（容器通道未实现，实际可不依赖） | git 约 50 MB；embeddable Python 约 15 MB |
| 使用者侧 | 需要一个浏览器打开界面 | — |
| 运行时读取的随包资源 | `backend/templates/train.py`（训练模板，按相对 `backend/` 定位）、`agents/prompts/*`（任务提示词，位于项目根） | 数 MB |

**结论**：本体 = 后端（Python 运行时 + 依赖）+ 前端 dist + 两类随包资源 + git + 「建环境兜底
解释器」；数据目录必须与程序目录分离（见下 P4）。

## 三、封装要解决的四个问题

- **P1 前端产物由谁服务**：打包后没有 vite——后端新增静态目录挂载（FastAPI `StaticFiles`
  服务 `frontend/dist`，同源、免跨域与双端口），或保留独立静态服务。推荐前者（一处端口、
  一处启动）。
- **P2 Python 运行时与依赖**：三种取法——(a) PyInstaller 把解释器+依赖打进可执行文件；
  (b) 携带完整便携 Python + site-packages 目录；(c) 要求使用者自装 Python（违背「一键」，
  仅作兜底说明）。
- **P3 硬依赖 git 与「建环境解释器」（定案：不捆绑，自检引导）**：git 由学生自装（Git for
  Windows，首次启动自检 + 缺装引导）；venv 分支用学生自装 Python（自检 `py` launcher / PATH，
  缺则引导安装）；conda 由学生自装（探测照旧、分支保留）。**不捆绑** MinGit / embeddable
  Python / Miniconda——评审定受众为在校学生（有一定基础），外置依赖自装可接受，体积与
  分发合规面同时下降。
- **P4 数据目录可写性与升级**：装进 `Program Files` 或解压目录不可写/升级即丢——数据目录
  默认挪到 `%LOCALAPPDATA%\DL-AI-skills\data`（`config.py` 需小改：`DATA_DIR` 支持环境变量
  或配置文件覆盖，打包模式下缺省即用户目录）；升级 = 换程序目录，数据目录不动。

## 四、候选方案

### A. PyInstaller 单目录（推荐候选）

后端 + 依赖打包为 `onedir` 可执行文件目录；`frontend/dist`、MinGit、embeddable Python、
`templates/`、`agents/prompts/` 作为资源目录并列；启动器 = exe（双击）→ 起后端 → 自动开
系统默认浏览器。

- 优点：最接近「双击即用」；对使用者零依赖要求；分发 = 拷贝一个目录（或压缩包）。
- 缺点：体积 400~600 MB；PyInstaller 对 pandas/pymupdf4llm/claude_agent_sdk 的兼容需实测
  （SDK 内部 CLI 的定位与临时解包）；杀毒软件对 PyInstaller 产物误报率高，可能需要签名。
- 变体：单文件 exe（更「一个文件」但启动要解包、更易误报、升级整包替换）——暂不推荐。

### B. 安装包（Inno Setup / NSIS）

便携 Python 运行时 + site-packages + dist + MinGit + 启动器打成安装程序；装完生成桌面
快捷方式「DL-AI-skills」；数据目录首次启动初始化到 `%LOCALAPPDATA%`。

- 优点：对「软件」的体感最正统；程序目录只读、数据目录分离天然成立；升级/卸载有标准语义。
- 缺点：多一道安装器制作与维护；与 A 的运行时内容几乎相同（A 是 B 的免安装形态）。

### C. Docker 镜像

后端 + 静态产物 + git 打进镜像，一条 `docker run` 起服务。

- 优点：跨机器环境一致；CI/服务器友好。
- 缺点：需要 Docker Desktop；界面仍在浏览器、无本机窗口整合；项目独立环境在容器内再建
  venv 可行，但 conda/GPU/本机目录挂载等能力受限；本项目容器通道从未启用（架构已定案
  conda/venv 为主线）——**列为备选，不推荐为主线**。

### D. Electron / Tauri 桌面壳

前端嵌进桌面窗口、后端作为子进程拉起，用户看到的是「一个桌面应用」而不是浏览器页。

- 优点：观感最完整（自带窗口、托盘可选）。
- 缺点：Electron 体积大（100 MB+ 壳 + 后端数百 MB）；Tauri 引入 Rust 工具链；对「一键执行」
  目标并无实质增益，浏览器页已能满足。列为可选增强，不进主线。

### E. 一键启动脚本（过渡形态，先行）

项目目录内 `start.bat`：自检（git / 后端解释器 / dist 在否，缺什么提示什么）→ 起后端 →
自动开浏览器。开发与联调期即用，也是 A/B 的前置验证物（先证明「一键启动」链路，再谈打包）。

**方案对比**：

| 维度 | A PyInstaller 单目录 | B 安装包 | C Docker | D 桌面壳 | E 启动脚本 |
|---|---|---|---|---|---|
| 一键程度 | 高（双击 exe） | 高（装完快捷方式） | 中（需装 Docker） | 高 | 中（需本机已配好环境） |
| 分发形态 | 目录/压缩包 | 安装程序 | 镜像 | 安装包/目录 | 源码目录 |
| 体积 | 大（400~600 MB） | 大 | 大 | 最大 | 无新增 |
| 维护成本 | 中（打包脚本 + 兼容实测） | 中上（安装器脚本） | 低 | 高 | 低 |
| 主要风险 | 兼容性、杀毒误报 | 安装器维护 | 能力受限（conda/GPU） | 双运行时复杂度 | 不解决分发 |

## 五、约束与风险（定案前需实测/确认）

1. **claude_agent_sdk 的 CLI 形态**：SDK 内部依赖 Claude Code CLI 二进制——打包时须实测
   SDK 在冻结环境下的 CLI 定位（是否写临时目录、是否被 PyInstaller 分析到）；分发合规沿用
   《开发计划》13.1 口径（二进制原样分发、使用者自备凭证）。
2. **PyInstaller 兼容面**：pandas/numpy/pymupdf4llm（原生扩展）与 SDK 的动态加载路径需
   实测；失败则回退 B（便携解释器 + site-packages，不冻结）。
3. **杀毒误报与签名**：PyInstaller 单文件误报率高于单目录；对外分发可考虑代码签名（成本
   另议）。
4. **数据目录迁移**：现有 `data/` 在项目根；打包后须按 P4 改 `config.py`（支持覆盖），并
   提供「发现旧数据目录 → 提示迁移或沿用」的首次启动逻辑。
5. **网络与镜像**：建环境装依赖仍需联网；封装产物应内置默认国内镜像源（`PIP_INDEX_URL`
   已有机制，打包时设默认值），并保留使用者改回官方源的入口。
6. **升级策略**：A 整目录替换（数据目录分离后无数据风险）；B 走安装器覆盖安装。
7. **conda 探测语义（定案）**：`CONDA_PATH` 探测照旧、conda 分支保留；**不捆绑**
   Miniconda——学生自装 conda（首次启动自检仅提示未安装、不阻断，用到 conda 分支时才需要）。

## 六、评审结论与定案路径

**评审结论（2026-10-05，用户裁定）**：
1. 目标平台：**仅 Windows**。
2. 受众：**在校学生**（有一定基础、不算标准开发人员）——git、conda、Python 等外置依赖
   **由学生自装**（首次启动自检 + 缺装引导），不捆绑进包。
3. 产物体积：接受大体积；具体产物见下「定案产物清单」。
4. 分发形态：**zip 压缩包**（方案 A 的 PyInstaller onedir 目录打包后压缩，非安装程序）。
5. conda 分支：**保留**（探测照旧，学生自装 conda，不捆绑 Miniconda）。
6. 凭证引导：**首次启动弹「设置凭证」页**（新增开发项：前端设置页 + 后端本地凭证存取；
   与规矩 7 一致——没凭证时大模型步骤如实失败，不静默、不伪造）。

**定案产物清单（zip）**：
- 文件名：`DL-AI-skills-<版本>-win64.zip`；解压到任意目录即用（建议路径无中文/空格）。
- 内容：`DL-AI-skills.exe`（启动器：自检 → 起后端 → 自动开浏览器）、`_internal/`（后端
  Python 运行时 + 全部依赖，PyInstaller onedir）、`static/`（前端 dist，后端 `StaticFiles`
  挂载同源服务）、`templates/train.py`、`agents/prompts/`（随包资源）。
- **不打包**：git、conda、建 venv 用的 Python（学生自装）、torch（训练在项目独立环境里装）。
- 体积：解压后约 350~500 MB、zip 约 150~300 MB（以打包实测为准）。
- 首次启动：自检 git/Python（缺则引导安装）→ 数据目录初始化 `%LOCALAPPDATA%\DL-AI-skills\data`
  （发现旧 `data/` 提示迁移或沿用）→ 自动开浏览器并弹「设置凭证」页 → pip 建环境默认国内
  镜像（保留改回官方源的入口）。
- 升级 = 换目录（数据目录分离，升级不丢数据）。

**定案后的实施路径**（《开发计划》阶段6 新增任务 **6.6**，实施细节随《阶段6实施方案》）：
1. 先行落地 **E**（`start.bat` 一键启动 + 后端挂静态目录 + 数据目录覆盖），阶段6 联调期即一键可跑；
2. 落地 **A**（PyInstaller onedir → zip），含新增「设置凭证」页与首次启动自检引导；
   若兼容实测受阻，回退「免安装便携版压缩包」（不冻结：便携 Python + site-packages + dist
   直接压缩，仍是 zip 形态，不再考虑安装程序 B）；
3. 设计登记落《系统架构设计》。
